# Validation du paysage et du CPU — V113

Lot du 26 septembre 2026. [Diagnostic et décision](../research/performance-v113.md). Le chunk de **présentation** passe de 16 à 64 cellules ; la recherche alimentaire des animaux évite deux balayages répétés et ne crée son index de repas qu'à partir de 16 repas végétaux actifs. Schéma 109, règles, catalogue, fixtures et PRNG métier inchangés. Cette page sépare les mesures natives, les replays et les contrôles de clôture.

## Rendu natif : monde mixte

Ryzen 5 3600, AMD RDNA1, Chromium matériel WebGPU, 1920×1080, zoom 0,23. Même sauvegarde publique `public/test-saves/v98/mixed-100.json` rétablie pour chaque phase : 104 personnes, 100 animaux, 11 009 ressources, tick initial 2000. Caméra immobile, quatre secondes mesurées après 1,3 seconde d'échauffement, sans export de monde pendant les fenêtres. Ordre ABBA : [16a](../../artifacts/performance-v113-abba-16a.json), [64a](../../artifacts/performance-v113-abba-64a.json), [64b](../../artifacts/performance-v113-abba-64b.json), [16b](../../artifacts/performance-v113-abba-16b.json). Les FPS ci-dessous sont `1000 / intervalle image moyen`, pas `1000 / p95`.

| Vitesse demandée | Chunk 16a / 16b : FPS ; image p95 | Chunk 64a / 64b : FPS ; image p95 | CPU de rendu p95, 16a / 16b → 64a / 64b |
|---|---:|---:|---:|
| Pause | 61,4 / 47,7 ; 20,9 / 25,1 ms | 236,5 / 216,7 ; 4,3 / 8,3 ms | 19,7 / 24,5 → 3,5 / 4,0 ms |
| ×1 | 43,4 / 31,3 ; 41,7 / 54,2 ms | 149,3 / 134,3 ; 20,8 / 25,0 ms | 36,9 / 48,3 → 13,4 / 16,1 ms |
| ×6 | 31,4 / 26,9 ; 62,5 / 62,5 ms | 105,4 / 120,7 ; 29,1 / 25,0 ms | 55,0 / 53,4 → 23,2 / 21,0 ms |

La soumission baisse nettement, mais le débit réel du worker à ×6 reste **2,355× / 1,566×** avec 16 et **2,077× / 1,646×** avec 64. Les valeurs de worker p95 à ×6 restent variables (89,1 / 126,1 ms avec 16 ; 103,5 / 128,8 ms avec 64). Ces passages ne prouvent ni une accélération de la simulation ni 240 FPS/6× constants. La baisse de la deuxième fenêtre 16 et du débit selon l'ordre est compatible avec une variabilité thermique ou système ; aucun chiffre isolé n'est choisi comme garantie.

[Timestamps GPU 16](../../artifacts/performance-v113-gpu-16.json) et [64](../../artifacts/performance-v113-gpu-64.json) dans des fenêtres séparées : à zoom 0,23, le p95 GPU est **3,80→3,93 ms** en pause et **3,41→4,46 ms** à ×6. Il s'agit du temps GPU résolu par Three, distinct de l'intervalle RAF et de la soumission CPU. Le nombre médian de dessins encodés en pause passe de 853 à 137, tandis que le nombre de triangles encodés monte de 1 625 621 à 2 078 671. Les bundles conservés faussent l'interprétation de `renderer.info` comme inventaire des dessins ou triangles réellement exécutés ; la réduction de CPU ne doit pas être attribuée à un GPU allégé.

Le [départ à trois colons, chunk 16](../../artifacts/performance-v113-start-16.json) et [chunk 64](../../artifacts/performance-v113-start-64.json) contrôle une autre charge au même zoom : FPS moyens **80,5→237,3** en pause, **66,2→220,1** à ×1 et **73,8→216,3** à ×6. Le débit ×6 est **5,970×→5,940×** : le rendu gagne, sans gain de simulation démontré. Les p95 d'image passent respectivement de 20,5 à 4,3 ms, 25,0 à 8,2 ms et 24,9 à 8,3 ms. Ce petit départ ne permet pas d'extrapoler la fluidité aux cent colons.

## Équivalence visuelle et continuité

Le [comparateur final](../../artifacts/chunk-visual-v113.json), relancé après correction du script, termine sans erreur JS/GPU : **14/14 états** V112/V113 ont zéro pixel différent, ombres comprises. Il contrôle aussi l'égalité des sommets, indices et indices d'ombre par couche, ainsi que la caméra, la lumière et le monde présentés. Les états comprennent première image, panoramique direct et répété, rotation, deux transitions de détail, croissance, minage, feuillage caché puis rétabli, rechargement réel avec panoramique et soleil déplacé. Les mutations de croissance/minage sont préparées pour isoler le rendu, sans travail de simulation. Le nombre de meshes baisse pour les couches remaillées, par exemple terrain 281→22, ressources 508→32 et roches 119→18 dans l'état initial ; cela n'enlève aucune géométrie globale.

Les deux builds ont `repeatedPanPixelEqual=true` et `reloadMatchesInitialPixels=false`. Les paires V112/V113 après rechargement sont identiques entre elles. Le dernier indicateur compare deux moments *dans* un build ; son résultat commun ne suffit pas à diagnostiquer une corruption de sauvegarde. Il reste à éclaircir séparément si l'état de référence et l'état rechargé étaient censés donner exactement les mêmes pixels.

Le [microbanc alimentaire](../../artifacts/performance-wildlife-food-v113.json) utilise le monde mixte immuable après 40 ticks d'échauffement, avec 100 animaux, 11 009 ressources et 2 983 candidats alimentaires. Les tableaux de candidats et les cibles sont comparés exactement avant les temps. En blocs ABBA entrelacés, 24 échantillons par variante, la recherche de nourriture passe de **13,568 à 2,513 ms en médiane** (p95 15,995→2,753 ms). Pour la réconciliation de 1/4/8/16/39 repas végétaux, les médianes recherche directe→index sont **0,101→1,279**, **0,409→1,123**, **0,685→1,001**, **1,449→1,066** et **3,421→1,108 ms**. Le seuil 16 évite donc de payer la construction de l'index lorsque seuls quelques repas sont actifs dans ce cas mesuré.

Le [replay CPU avant](../../artifacts/performance-cpu-v113-before.json), les [replays après index](../../artifacts/performance-cpu-v113-after-index.json) / [répété](../../artifacts/performance-cpu-v113-after-index-b.json) et le [passage final avec seuil 16](../../artifacts/performance-cpu-v113-after-threshold.json) exécutent 40 ticks d'échauffement puis 120 ticks avec capture, encodage, copie et décodage de chaque publication. Tous finissent au tick 2160 avec le même PRNG `63279223` et le même SHA-256 de sauvegarde `b6da34e670bfa65f8f520fd4f8936e85c67460eb9f3c38a641a3787604bc623e`. Le p95 du tick varie : 93,99 ms avant, 71,90 ms dans un passage après index, 93,73 ms dans sa répétition et 83,05 ms avec le seuil final. La conservation est établie sur ce replay ; le gain global du worker n'est pas établi par ces mesures Node.

## Contrôles de clôture

Huit fichiers de tests ciblés passent, soit **27 contrôles**, dont deltas de ressources/flore, commandes conservées, faune et snapshots. `npm run build` passe avec typage TypeScript ; l'avertissement historique de taille du bundle subsiste. `npm run test:presentation` passe : mine puis coupe sur 250², sans saut ni occupation d'une roche, avec commandes vérifiées. La première tentative de tests ciblés dans le sandbox s'est arrêtée au chargement de Vite sur `spawn EPERM` ; la même commande relancée avec les permissions nécessaires passe. La suite globale n'est pas revendiquée : sa dette V90/V84 connue reste à réconcilier selon [ROADMAP](../ROADMAP.md).

`python scripts/check-docs.py` passe : 405 documents, 4 457 liens locaux, 25 domaines et cinq familles de validation conservés ; les trois sources originales sont octet pour octet identiques. `git diff --check` passe, sans erreur d'espacement (seuls avertissements de fin de ligne CRLF→LF). Aucune publication Netlify n'est annoncée pour V113 : le site public est resté en V109 lors des lots récents faute de crédits. G0–G4 partiels, G5 absent ; aucune estimation fonctionnelle ne progresse par ce seul lot.
