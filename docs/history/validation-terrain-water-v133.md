# Validation terrain et eau V133

- `npm test -- tests/terrain-water-v133.test.ts tests/terrain-paint-v132.test.ts` : 6/6 contrôles. Les octets du recuit local sont identiques à un recuit neuf après conversion d'une case en eau ; les UV eau/sol et les six indices/case restent continus entre chunks.
- `npm run build` et typage TypeScript : réussis. `git diff --check` : aucune erreur d'espacement.
- `npx playwright test tests/integration/terrain-water-v133.spec.ts` : 1/1 en Chromium **WebGPU natif**. Contrôle de l'atlas 256² partagé, eau proche et vue éloignée, même version d'atlas après zoom, uniforme d'eau figé pendant la pause, libération de l'atlas à 1×1 et suppression des UV au mode textures désactivées, puis reconstruction et UV rétablis à la réactivation. Aucune erreur JS ou validation GPU observée. Les captures locales `artifacts/terrain-water-v133-close.png` et `artifacts/terrain-water-v133-distant.png` sont régénérables par ce pilote. Il crée une mare et fixe le tick dans le renderer pour inspecter l'éclairage ; le HUD conserve l'heure de la partie worker et n'est pas une preuve de progression diurne de celle-ci.

Sur 250×250, le test local mesure **1 166 ms** pour le recuit initial de 16 Mo RGBA et **0,19 ms CPU** pour les 576 pixels d'un changement de case, dans la plage V132 malgré les frontières plus complexes grâce au cache de ligne/colonne. Les mipmaps portent la carte à environ 21,3 Mo. Le patch reste local sur CPU, mais Three 0.186 WebGPU renvoie l'image complète et reconstruit les mipmaps ; ce coût GPU n'a pas été isolé. Le terrain/eau peint ajoute un échantillon de texture sur les fragments d'eau visibles et deux ondes trigonométriques ; le parcours n'est pas une mesure comparative fiable de FPS. Aucun objectif 240 FPS/×6 ni équivalence stricte de performance n'est revendiqué.
