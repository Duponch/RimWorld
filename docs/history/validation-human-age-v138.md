# Validation V138 — âges humains

28 septembre 2026. Le [contrat](../development/human-age-v138.md) et le [relevé Core 1.6.4871](../research/human-age-core-v138.md) bornent la portée : deux compteurs d'âge, deux affections chroniques, effets sur capacités et immunité. Les sources primaires sont les définitions de l'installation Core et les classes `Pawn_AgeTracker`, `PawnGenerator`, `AgeInjuryUtility` et `StatPart_Age` de la même version ; l'annonce [Ludeon](https://ludeon.com/blog/2015/02/rimworld-alpha-9-tales-o-drunkness-released/) donne le contexte public des deux âges.

Les tests V138 couvrent la génération adulte et déterministe, la distribution cryptosommeil des trois colons Crashlanded, le rejeu initial des deux affections chez un nouvel adulte âgé, le franchissement d'anniversaire, les pertes de capacités, le facteur d'immunité, la pause et les ticks confirmés, la continuation identique après sauvegarde, puis le refus des champs futurs avant migration V135. Un test de visiteur archivé contrôle son âge gelé, la migration neutre et le rejet atomique d'une entrée ou d'un pion manquant. Les voies d'arrivée, de raid, de visite et de rencontre emploient toutes la même fabrique d'acteurs. Le typage TypeScript passe.

Le groupe ciblé `human-age-v138`, `visitors` et `flu` compte **18 tests réussis sur 18**. Le groupe étendu qui ajoute `arrivals` et `raids` passe **31/31**. Deux anciens oracles V65/V67 forgeaient des politiques alimentaires contenant du lait V120 et des loisirs V122/V124 dans des sauvegardes déclarées antérieures à V80 ; les constructeurs de fixtures ont été corrigés sans toucher au validateur ou aux fichiers historiques. Quatre autres dossiers de sauvegarde, dont V79, V80 et V106, passent **12/12** après alignement des attentes sur les migrations V120–V138. `npm run build` passe. Le parcours `tests/integration/human-age-v138.spec.ts` passe **1/1** sous Chromium/WebGPU : Bio et Santé montrent le même âge persisté et les deux affections. Ces contrôles ne prouvent ni toutes les interfaces Core ni une campagne longue.

Le microbanc reproductible `node --experimental-strip-types scripts/human-age-bench-v138.ts` isole `advanceHumanAges` sur **100 acteurs × 3 000 ticks**, 15 répétitions, Ryzen 5 3600 et Node 24.11.1. Médiane **1,379 ms** sans anniversaire et **1,462 ms** quand les 100 acteurs franchissent 80 ans une fois pendant le parcours ; minima **1,273 / 1,389 ms**, maxima **4,424 / 5,461 ms**. Cela mesure le cumul de l'appel d'âge seulement, sans worker complet, navigation, soins, rendu ou GPU. Ce n'est ni un profil FPS, ni une preuve de débit ×6 ou de 240 FPS. Les anniversaires peuvent changer le PRNG et ajouter un dossier médical ; les ticks ordinaires ne font aucun tirage d'âge.
