# Phases de réception stricte V245

V245 attribue les coûts du SnapshotDecoder actuel dans le vrai jeu, sans nouveau code produit ni gain de FPS. Produit V242 et schéma 198 conservés. [Mesures et limites](../history/validation-adoption-phases-v245.md).

Le module canonique `src/bridge/snapshots.ts` reste unique. Une transformation privée ajoute un token, dix-sept transitions de phase et un `finally` autour de toute la méthode `adopt`. Les instructions, imports historiques, prédicats, lectures d'entrée, retours et exceptions gardent leur ordre ; l'inverse RAW entier retrouve la source originale. La copie de typage n'est jamais chargée dans le jeu. Le helper et le main partagent un seul ID de module par realm ; le worker ne reçoit aucune fenêtre de mesure.

La fenêtre reprend les bornes exactes du probe GAME qualifié. Chaque enfant hérite du verdict true ou false de son parent ; les dépassements de fenêtre sont déclarés. Refus, stale et exceptions ferment le scope sans changer leur résultat. Les agrégats count/sum/min/max couvrent tous les segments ; seuls les 128 premiers échantillons par phase sont conservés, sans percentile exhaustif. Pile bornée à 256, phases fixes, anomalies, troncatures et pertes d'agrégats explicites. Le harness refuse toute anomalie de cycle ou d'horloge ; il conserve les erreurs HTTP, navigateur et GPU.

Les phases séparent normalisation des structures, gardes de forme, reconstruction terrain/ressources/piles, World assemblé, propriétaires locaux, contrôle végétal, autres gardes, construction du tableau owners, registre d'identités, validations mécaniques/planétaires/projectiles, relations finales, index et publication. `namespaceIds` inclut les ajouts hors carte et archives ; ce n'est pas le coût des seules ressources. La phase précédente `namespaceAssembly` mesure le tableau owners dans son ordre historique. Aucune phase n'ajoute un compteur ou un scan du World.

La fenêtre observée comporte 170 adoptions, toutes complètes et sans réentrance. Construction owners et registre coûtent ensemble environ 1,848 ms sur un parent de 5,491 ms ; le contrôle végétal final coûte 1,248 ms. Ces blocs motivent une refonte combinée, sans annoncer leur suppression totale. Le coût de preuve, fermeture et repli doit rester dans les mesures : [V234](native-resource-ownership-v234.md) avait déjà écarté la fermeture végétale seule. Le prototype de namespace numérique n'a pas encore un propriétaire admissible ou une preuve complète de non-échappement.

La prochaine qualification doit conserver le prefix joué avant Resource, les premiers motifs et ordinals de refus, la vraie instance/ordre du registre et les anciennes vues. Toute interposition impose la matérialisation historique avant que le registre échappe. Les consommateurs et validations suivants doivent réellement conserver l'économie ; la retirer puis réinsérer N avant leur premier appel serait inutile. Aucun raw/bool/stamp n'accorde une autorité native. Coût complet, froid et contreparties avant GAME et adoption ; aucune nouvelle mécanique, cadence ou qualité réduite.
